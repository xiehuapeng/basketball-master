# 项目状态与路线图

## 当前状态

当前阶段：`MVP 工程版`

本阶段目标是把“本地实验脚本”升级成“可持续迭代的产品项目骨架”，并确认核心视频分析链路是真的能跑通、能解释、能继续优化。

## 已完成事项

### 代码结构

- 已建立 `src/basketball_analyzer` 包结构
- 已拆分 `analysis`、`rendering`、`detection`、`service` 等模块
- 已保留原实验脚本，方便回溯算法来源

### 交付入口

- 已提供 CLI
- 已提供 FastAPI API
- 已提供标准化 JSON 输出

### 运行验证

- 已跑通单视频分析
- 已跑通球星动作对比
- 已跑通 FastAPI 健康检查
- 已跑通 FastAPI 单视频分析接口
- 已跑通 FastAPI 对比分析接口

### 篮球检测与离手修正

- 已完成远端篮球检测的可插拔接入层
- 已支持 `Roboflow` 和 `Hugging Face`
- 已增加批量模型评估入口
- 已筛出当前默认优先模型：`basketball-game-detections/9`
- 已将篮球检测框叠加到输出视频
- 已支持“姿态离手帧 / 最后贴手帧 / 最终离手帧 / 球手分离帧”的统一输出
- 已支持在姿态离手帧可疑时向前回溯视频帧，寻找“最后贴手帧 -> 下一帧离手”的转换点

## 当前关键结论

- 当前项目已经不是脚本集合，而是可继续演进的 MVP 工程
- 篮球检测已经不仅能“确认”离手帧，还能“修正”离手帧
- 对 `shooting.mp4` 的最新真实验证中，离手帧已从 `175` 修正为 `150`
- `149` 被识别为最后贴手帧，`150` 更接近“刚离手”的定义

## 当前框架图

```text
上传视频
  -> API / CLI
  -> AnalysisService
  -> Pose 提取
  -> 投篮片段定位
  -> 姿态离手帧
  -> 可选篮球检测回溯
  -> 最后贴手帧 / 最终离手帧修正
  -> 视频 / 截图 / JSON 输出
```

## 当前风险

- 当前球手分离规则仍偏启发式，阈值对视频质量较敏感
- `shoot1.mp4` 这类样本上，现成 Hosted 模型仍然容易漏检
- 对比分析已可用，但参考视频定位在部分样本上还不够稳定
