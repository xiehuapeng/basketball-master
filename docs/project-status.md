  （HF `Lumos-88/YOLO11-fine-tuned-for-basketball-detection`），可用 `--local-model-path yolov8n.pt` 切换 COCO 通用模型
- 已增加批量模型评估入口（`ball-eval` 支持 local provider）

- 已支持 `ball-flight-bound`：球在更早帧已飞行时，把离手帧回溯到飞行首帧的上界
- 已支持"球贴手贯穿 pose 帧"时把离手帧向后推进到贴手段末尾的下一帧
- 距离归一为肩宽倍数 + 球半径倍数双重判定，扩大搜索窗口按 fps 自适应缩放

### 姿态与人物鲁棒性

- 主手判定升级为多信号融合（腕速度 + 举过肩幅度 + 可见度加权）
- 主体人物锁定：髋部中心 + 身体尺度时序连续性过滤，多人/误检帧被剔除
- 远景小人物自适应：`filter_frames` 在默认 box-area 阈值过滤后帧数过少时，按视频自身人体尺寸中位数自动放宽

## 当前关键结论（截至 2026-08-04 实测）

- 当前项目已经不是脚本集合，而是可继续演进的 MVP 工程
- 篮球检测已经不仅能"确认"离手帧，还能"修正"离手帧（向前回溯和向后推进双向）
- **纠错**：旧文档中"`shooting.mp4` 离手帧为 150"的结论有误。逐帧人工核验表明
  150 帧球仍在手上，160 帧仍在指尖，162 帧已飞出，真实离手 ≈ 161 帧。
  当前算法输出 164（ball-flight-bound），误差 +3 帧；纯姿态启发式为 172（误差 +11）
- 全量回归结果（provider=local，默认篮球微调模型）：

| 视频 | pose 帧 | 最终帧 | 来源 | 人工核验 |
| --- | --- | --- | --- | --- |
| shooting.mp4 | 172 | 164 | ball-flight-bound | 真值≈161，误差 +3 |
| shoot1.mp4 | 109 | 109 | pose+ball | 准确 |
| curry.mp4 | 80 | 80 | pose（远候选拒绝） | 准确 |
| testdata/gh_shot_arc.mp4 | 37 | 37 | pose+ball | 偏晚（微调模型把手误检为球；yolov8n 给 26 更准） |
| testdata/gh_outdoor_clip1.mp4 | 95 | 85 | ball-contact-transition | 准确 |
| testdata/gh_outdoor_clip2.mp4 | 44 | 44 | ball-contact-transition | 准确 |
| testdata/gh_outdoor_clip3.mp4 | 65 | 70 | ball-contact-transition | 准确（球贴手贯穿 pose 帧，向后推进） |

- 球检测率：篮球微调模型在 shooting / shoot1 / curry 上均 100%（Roboflow Hosted 在 shoot1 上为 0%）

## 当前框架图

```text
上传视频
  -> 网页上传页 / API / CLI
  -> 异步任务队列（/tasks/*）
  -> AnalysisService
  -> Pose 提取
  -> 主体人物锁定 + 远景自适应过滤
  -> 投篮片段定位
  -> 姿态离手帧
  -> 本地 YOLO 篮球检测（可选远端）
  -> 轨迹分类（静止球抑制 / 飞行证据）
  -> 最后贴手帧 / 最终离手帧修正（双向）
  -> 视频 / 截图 / JSON 输出
```

## 当前风险 / 已知限制

- 篮球微调模型在全身远景场景（如 `gh_shot_arc.mp4`）会把双手误检为球，
  导致假"贴手确认"；该类视频建议 `--local-model-path yolov8n.pt`
- 举球阶段双手遮挡时手中球易漏检，无法找到真实贴手帧（shooting.mp4 只能靠飞行上界回溯到 164）
- 多次连续投篮的长视频仍按单次投篮处理，需要先切片（见 `testdata/` 切片示例）
- 异步任务表为内存态，服务重启后任务记录丢失
- 当前上传页是 MVP 内嵌页面，尚未限制上传大小、持久化任务或实现用户隔离
- 本地模型权重需要另行下载；商业产品使用前需复核模型数据来源和 Ultralytics 许可边界
